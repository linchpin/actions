---
title: Secrets and variables
---

Every secret and variable the shared workflows read, and which workflows read it. Each workflow's own page lists the secrets it declares.

## Where they live

- **Secrets** reach a reusable workflow only when the caller passes them, either one by one or with `secrets: inherit`. A workflow sees organization secrets the same way, as long as the caller passes them.
- **Variables** are read from the calling repository's `vars` context: the GitHub environment the job deploys to, then the repository, then the organization. Set per-environment values like `SITE_ID`, `SITE_URL` and `BRANCH` on the GitHub environment, so staging and production differ.
- Composer credentials travel as the `COMPOSER_AUTH` environment variable, never as an `auth.json` on disk.
- `GITHUB_TOKEN` is the job token GitHub provides to every run. Nothing needs setting for it. `wp-version-checker.yml` passes it to the version check, and every workflow's **Permissions** table says what it is granted.
